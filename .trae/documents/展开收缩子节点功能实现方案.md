# vue-json-pretty 展开/收缩所有子节点功能实现方案

## 一、需求分析

用户希望在选中节点时，能够通过操作按钮实现：
1. **展开当前节点下的子节点**（支持层级控制）
2. **收缩当前节点下的子节点**（支持层级控制）

### 层级控制需求
用户希望能够控制展开/收缩的层级深度：
- **第一级子节点**：只展开/收缩选中节点下的直接子节点（不包含更深层的嵌套）
- **所有子节点**：展开/收缩选中节点下的所有子节点（包含所有深层嵌套）
- **指定层级**：展开/收缩指定深度的子节点（如：展开前 2 层）

### 当前组件状态
- Tree 组件内部通过 `state.hiddenPaths` 维护折叠状态
- `hiddenPaths` 是一个对象，key 为节点 path，value 为 1
- 当节点 path 在 `hiddenPaths` 中时，该节点及其子节点被折叠
- 目前组件未暴露任何控制折叠状态的方法给外部

### 与现有 `deep` 属性的关系
- **`deep` 属性**：用于控制**初始渲染**时的折叠深度，大于该深度的节点将被折叠
- **新增功能**：提供运行时的展开/收缩方法，用户可以动态控制节点的折叠状态
- **不冲突**：`deep` 是初始化设置，新增的方法是运行时操作，两者互不影响

## 二、实现方案

采用**组合方案**，提供多种使用方式以满足不同场景需求：

### 方案 A：通过 ref 暴露方法（推荐）

#### 优点
- 使用简单直观
- 符合 Vue 3 组合式 API 设计理念
- 便于在复杂业务逻辑中调用

#### 实现步骤

**1. 在 Tree 组件中添加 expose**

在 `src/components/Tree/index.tsx` 中：

```typescript
setup(props, { emit, slots, expose }) {
  // ... 现有代码 ...

  // 获取指定节点下的子节点路径（支持层级控制）
  // depth: 层级深度
  //   - 1: 只获取第一级子节点
  //   - 2: 获取前两级子节点
  //   - Infinity: 获取所有子节点
  const getChildrenPaths = (path: string, depth: number = Infinity): string[] => {
    const children: string[] = [];
    const originData = originFlatData.value;
    
    // 获取父节点的层级
    const parentNode = originData.find(item => item.path === path);
    if (!parentNode) return children;
    
    const parentLevel = parentNode.level;
    const maxLevel = depth === Infinity ? Infinity : parentLevel + depth;
    
    for (let i = 0; i < originData.length; i++) {
      const item = originData[i];
      
      // 判断是否为子节点：
      // 1. 路径以父路径开头
      // 2. 不是父节点本身
      // 3. 是对象或数组的起始节点（可折叠节点）
      // 4. 层级在指定范围内
      if (
        (item.path.startsWith(path + '.') || item.path.startsWith(path + '[')) &&
        item.path !== path &&
        (item.type === 'objectStart' || item.type === 'arrayStart') &&
        item.level <= maxLevel
      ) {
        children.push(item.path);
      }
    }
    
    return children;
  };

  // 展开指定节点下的子节点
  // path: 节点路径，不传则展开所有节点
  // depth: 层级深度，默认 Infinity（所有层级）
  const expandAll = (path?: string, depth: number = Infinity) => {
    if (!path) {
      // 如果没有指定路径，展开所有节点
      state.hiddenPaths = {};
      return;
    }

    const childrenPaths = getChildrenPaths(path, depth);
    const newHiddenPaths = { ...state.hiddenPaths };
    
    childrenPaths.forEach(childPath => {
      delete newHiddenPaths[childPath];
    });
    
    state.hiddenPaths = newHiddenPaths;
  };

  // 收缩指定节点下的子节点
  // path: 节点路径，不传则收缩所有节点
  // depth: 层级深度，默认 Infinity（所有层级）
  const collapseAll = (path?: string, depth: number = Infinity) => {
    if (!path) {
      // 如果没有指定路径，收缩所有节点
      state.hiddenPaths = initHiddenPaths(props.deep, props.collapsedNodeLength);
      return;
    }

    const childrenPaths = getChildrenPaths(path, depth);
    const newHiddenPaths = { ...state.hiddenPaths };
    
    childrenPaths.forEach(childPath => {
      newHiddenPaths[childPath] = 1;
    });
    
    state.hiddenPaths = newHiddenPaths;
  };

  // 暴露方法给外部
  expose({
    expandAll,
    collapseAll,
    getChildrenPaths,
  });

  // ... 其余代码 ...
}
```

### 方案 B：在 renderNodeActions slot 中提供方法

#### 优点
- 无需使用 ref
- 操作按钮直接在 slot 中定义，逻辑更内聚
- 适合简单的操作场景

#### 实现步骤

**1. 修改 TreeNode 组件**

在 `src/components/TreeNode/index.tsx` 中，修改 renderNodeActions 的参数：

```typescript
const renderNodeActions = () => {
  const render = props.renderNodeActions;
  if (!render) return null;
  
  const defaultActions = {
    copy: handleCopy,
  };

  // 新增：展开/收缩方法（支持层级控制）
  const nodeActions = {
    expandAll: (depth: number = Infinity) => emit('expandAll', props.node.path, depth),
    collapseAll: (depth: number = Infinity) => emit('collapseAll', props.node.path, depth),
    // 便捷方法：展开/收缩第一级
    expandFirstLevel: () => emit('expandAll', props.node.path, 1),
    collapseFirstLevel: () => emit('collapseAll', props.node.path, 1),
  };

  return typeof render === 'function' ? (
    render({ 
      node: props.node, 
      defaultActions,
      ...nodeActions  // 展开方法
    })
  ) : (
    <span onClick={handleCopy} class="vjs-tree-node-actions-item">
      copy
    </span>
  );
};
```

### 方案 C：通过 props 控制折叠状态（不推荐）

#### ⚠️ 注意事项
此方案与现有的 `deep` 属性存在概念冲突：
- `deep` 属性用于控制初始渲染时的折叠深度
- 新增 `collapsedPaths` props 会导致状态管理复杂化
- 用户需要同时理解两个属性的作用和优先级

#### 替代建议
**不推荐实现此方案**，原因如下：
1. **方案 A 和 B 已经足够**：通过方法调用可以满足所有需求
2. **避免状态冲突**：不需要引入新的 props 来管理折叠状态
3. **保持简洁**：组件 API 更清晰，用户更容易理解

如果确实需要持久化折叠状态，建议：
- 使用方案 A 的 `getChildrenPaths()` 方法获取折叠路径
- 在用户代码中自行管理折叠状态
- 通过 `deep` 属性控制初始折叠深度

## 三、推荐方案

**推荐采用方案 A + 方案 B 的组合方式：**

1. **主要使用方案 A（ref 暴露方法）**
   - 提供完整的方法 API
   - 便于在复杂场景中使用
   - 支持层级控制

2. **同时支持方案 B（slot 参数）**
   - 提供便捷的使用方式
   - 适合简单场景
   - 代码更简洁

3. **不推荐方案 C**
   - 与现有 `deep` 属性存在概念冲突
   - 方案 A 和 B 已经足够满足需求
   - 避免增加组件 API 的复杂度

### 层级控制逻辑说明

**层级深度参数说明：**
- `depth = 1`：只操作第一级子节点
- `depth = 2`：操作前两级子节点
- `depth = Infinity`：操作所有子节点（默认）

**示例场景：**

假设有以下 JSON 结构：
```json
{
  "user": {
    "name": "John",
    "address": {
      "city": "New York",
      "zip": "10001"
    },
    "tags": ["admin", "user"]
  }
}
```

对应的节点路径和层级：
```
root (level 0)
├─ root.user (level 1)
│  ├─ root.user.name (level 2)
│  ├─ root.user.address (level 2)
│  │  ├─ root.user.address.city (level 3)
│  │  └─ root.user.address.zip (level 3)
│  └─ root.user.tags (level 2)
│     ├─ root.user.tags[0] (level 3)
│     └─ root.user.tags[1] (level 3)
```

**操作示例：**

1. **展开第一级子节点** (`expandAll('root.user', 1)`)
   - 只展开 `root.user.name`、`root.user.address`、`root.user.tags`
   - `root.user.address` 和 `root.user.tags` 仍然保持折叠状态

2. **展开所有子节点** (`expandAll('root.user')`)
   - 展开所有子节点，包括深层嵌套的节点

3. **收缩第一级子节点** (`collapseAll('root.user', 1)`)
   - 只收缩 `root.user.name`、`root.user.address`、`root.user.tags`
   - 不影响更深层的节点

4. **收缩所有子节点** (`collapseAll('root.user')`)
   - 收缩所有子节点，包括深层嵌套的节点

### 路径匹配逻辑说明

节点的 path 格式示例：
- 根节点：`root`
- 对象属性：`root.user`, `root.user.name`
- 数组元素：`root.items[0]`, `root.items[0].title`

判断子节点的逻辑：
```typescript
// 对于父节点 root.user
// 子节点可能是：
// - root.user.name (对象属性)
// - root.user.address (对象属性)
// - root.user.tags[0] (数组元素)

// 判断方式：
item.path.startsWith(parentPath + '.') ||  // 对象属性
item.path.startsWith(parentPath + '[')      // 数组元素
```

## 九、总结

本方案通过组合多种实现方式，为用户提供了灵活便捷的展开/收缩子节点功能，并支持层级控制：

### 核心特性
1. **层级控制**：支持精确控制展开/收缩的层级深度
   - 第一级子节点：只操作直接子节点
   - 所有子节点：操作所有深层嵌套节点
   - 指定层级：操作指定深度的子节点

2. **多种使用方式**：
   - **ref 方式**：适合复杂业务逻辑，方法调用清晰
   - **slot 参数方式**：适合简单场景，代码更简洁

3. **便捷方法**：
   - `expandFirstLevel()` / `collapseFirstLevel()`：快速操作第一级子节点
   - `expandAll(depth)` / `collapseAll(depth)`：灵活控制层级深度

### API 设计
```typescript
// Tree 组件暴露的方法
expandAll(path?: string, depth?: number): void
collapseAll(path?: string, depth?: number): void
getChildrenPaths(path: string, depth?: number): string[]

// slot 参数中的方法
expandAll(depth?: number): void
collapseAll(depth?: number): void
expandFirstLevel(): void
collapseFirstLevel(): void
```

### 与现有功能的关系
- **`deep` 属性**：控制初始渲染时的折叠深度
- **新增方法**：提供运行时的展开/收缩操作
- **互不影响**：两者可以配合使用，不会产生冲突

### 使用建议
- **简单场景**：使用 slot 参数方式，代码更简洁
- **复杂场景**：使用 ref 方式，便于在业务逻辑中调用
- **需要持久化状态**：使用 `getChildrenPaths()` 方法获取折叠路径，自行管理状态

推荐实现方案 A 和方案 B，满足所有使用场景需求。
