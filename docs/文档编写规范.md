# 技术文档编写规范（通用版）

本文档定义了技术项目文档的编写规范，基于业界最佳实践（2025-2026）和 Diátaxis 框架。

---

## 一、文档类型分类（Diátaxis 框架）

业界广泛采用的文档分类方法，将文档分为四种类型：

| 类型 | 导向 | 目的 | 结构 |
|------|------|------|------|
| **Tutorials** | 学习导向 | 教学概念，引导实践 | 学习目标 → 前置条件 → 步骤 → 验证 |
| **How-to Guides** | 问题导向 | 解决具体问题 | 问题陈述 → 前置条件 → 解决步骤 → 故障排除 |
| **Reference** | 信息导向 | 提供详细参考信息 | 按字母或逻辑分组 → 参数说明 → 代码示例 |
| **Explanations** | 理解导向 | 解释概念和架构 | 概念介绍 → 背景 → 图解 → 示例 |

### 1.1 Tutorials（教程）

**特点**：学习导向，适合新手

**结构**：
```markdown
# [教程标题]

> 一句话概述

## 学习目标
- 目标 1
- 目标 2

## 前置条件
- 条件 1
- 条件 2

## 步骤
### 步骤 1：[标题]
[说明]

### 步骤 2：[标题]
[说明]

## 验证
[如何确认成功]

## 下一步
[相关资源]
```

**示例**：
```markdown
# 快速开始

> 5 分钟快速上手组件库

## 学习目标
- 安装并引入组件
- 渲染第一个组件
- 理解基本配置

## 前置条件
- Vue 3.x 项目
- Node.js 14+

## 步骤
### 步骤 1：安装

\`\`\`bash
npm install your-component-library
\`\`\`

### 步骤 2：引入组件

\`\`\`vue
<template>
  <YourComponent :data="data" />
</template>

<script setup>
import { ref } from 'vue';
import YourComponent from 'your-component-library';

const data = ref({ name: 'example' });
</script>
\`\`\`

## 验证
打开浏览器，应该能看到组件正常渲染。

## 下一步
- [如何自定义样式](指南/如何自定义样式.md)
- [如何处理事件](指南/如何处理事件.md)
```

### 1.2 How-to Guides（操作指南）

**特点**：问题导向，解决具体问题

**结构**：
```markdown
# 如何 [做某事]？

## 问题描述
[要解决什么问题]

## 前置条件
- 条件 1
- 条件 2

## 解决步骤
1. 步骤 1
2. 步骤 2

## 故障排除
- 问题 1：解决方案
- 问题 2：解决方案
```

**示例**：
```markdown
# 如何自定义组件样式？

## 问题描述
用户需要自定义组件的外观，包括颜色、字体、间距等样式属性。

## 前置条件
- 已安装组件库
- 已了解基础的组件使用

## 解决步骤

### 方案 1：通过 props 自定义

\`\`\`vue
<template>
  <YourComponent 
    :custom-style="{ color: 'red', fontSize: '16px' }"
  />
</template>
\`\`\`

### 方案 2：通过 CSS 覆盖

\`\`\`css
.your-component-class {
  color: red;
  font-size: 16px;
}
\`\`\`

## 故障排除

### 问题：样式不生效

**原因**：CSS 优先级不够

**解决方案**：使用 `!important` 或更具体的选择器

### 问题：主题切换失效

**原因**：未使用 CSS 变量

**解决方案**：使用 CSS 变量定义样式
```

### 1.3 Reference（参考文档）

**特点**：信息导向，提供详细参考

**结构**：
```markdown
# [API/配置] 参考

## 概述
[简要说明]

## 参数
| 参数 | 类型 | 必填 | 默认值 | 说明 |
|------|------|------|--------|------|
| param1 | string | 是 | - | 说明 |

## 返回值
[返回值说明]

## 示例
[代码示例]

## 注意事项
[重要提示]
```

**示例**：
```markdown
# Props 配置参考

## 概述
组件支持以下 props 配置。

## 参数

### data

**类型**：`Object | Array`

**必填**：是

**默认值**：无

**说明**：要渲染的数据对象或数组

**示例**：
\`\`\`vue
<template>
  <YourComponent :data="jsonData" />
</template>

<script setup>
const jsonData = {
  name: 'example',
  items: [1, 2, 3]
};
</script>
\`\`\`

---

### theme

**类型**：`'light' | 'dark'`

**必填**：否

**默认值**：`'light'`

**说明**：主题模式

**示例**：
\`\`\`vue
<YourComponent theme="dark" :data="data" />
\`\`\`

## 注意事项

1. **数据格式**：确保数据格式正确
2. **性能优化**：大数据量时使用虚拟滚动
3. **响应式**：数据变化会自动更新视图
```

### 1.4 Explanations（解释文档）

**特点**：理解导向，解释概念

**结构**：
```markdown
# [概念] 详解

## 什么是 [概念]？
[定义]

## 为什么需要 [概念]？
[背景和原因]

## 如何工作？
[原理说明]

## 示例
[实际案例]
```

**示例**：
```markdown
# 虚拟滚动原理详解

## 什么是虚拟滚动？

虚拟滚动是一种性能优化技术，只渲染可视区域内的元素，而不是渲染整个列表。

## 为什么需要虚拟滚动？

当列表数据量很大时（如 10000 条），如果全部渲染：
- DOM 节点过多，导致页面卡顿
- 内存占用过高
- 滚动性能下降

虚拟滚动可以：
- 只渲染可见区域的元素（如 20 个）
- 大幅减少 DOM 节点数量
- 提升滚动性能

## 如何工作？

### 基本原理

1. **计算可视区域**：确定可见区域能显示多少个元素
2. **计算位置**：根据滚动位置计算应该显示哪些元素
3. **渲染元素**：只渲染可视区域内的元素
4. **占位容器**：使用占位容器撑开滚动条高度

### 示意图

\`\`\`
┌─────────────────┐
│  占位容器顶部    │  ← 不可见
├─────────────────┤
│  元素 1         │
│  元素 2         │  ← 可视区域
│  元素 3         │
├─────────────────┤
│  占位容器底部    │  ← 不可见
└─────────────────┘
\`\`\`

## 示例

\`\`\`vue
<template>
  <VirtualScroll 
    :items="largeList"
    :item-height="50"
    :visible-count="20"
  >
    <template #default="{ item }">
      <div class="item">{{ item.name }}</div>
    </template>
  </VirtualScroll>
</template>
\`\`\`
```

## 二、文档层次结构

### 2.1 推荐目录结构

```
docs/
├── README.md                    # 文档导航首页
├── 快速开始.md                   # Getting Started
│
├── 指南/                        # Guides（How-to Guides）
│   ├── 如何自定义样式.md
│   ├── 如何处理事件.md
│   ├── 如何优化性能.md
│   └── ...
│
├── 参考/                        # Reference
│   ├── Props配置.md
│   ├── Events事件.md
│   ├── Methods方法.md
│   └── ...
│
├── 组件文档/                    # Component Docs（可选）
│   └── ...
│
└── 概念/                        # Explanations（可选）
    ├── 架构设计.md
    └── 性能优化原理.md
```

### 2.2 目录命名规范

| 目录类型 | 命名 | 说明 |
|---------|------|------|
| 快速入门 | `快速开始.md` 或 `getting-started.md` | 新手入门指南 |
| 操作指南 | `指南/` 或 `guides/` | 操作类文档 |
| 参考文档 | `参考/` 或 `reference/` | API、配置参考 |
| 组件文档 | `组件文档/` 或 `components/` | 组件使用文档 |
| 概念解释 | `概念/` 或 `concepts/` | 概念解释文档 |

## 三、文档设计原则

### 3.1 MECE 法则

- **相互独立（Mutually Exclusive）**：各文档之间边界清晰，不重叠
- **完全穷尽（Collectively Exhaustive）**：覆盖所有必要内容，无遗漏

**示例**：
```
✅ 正确：
├── Props配置.md        # Props 配置
├── Events事件.md       # Events 事件
├── Methods方法.md      # Methods 方法

❌ 错误：
├── API文档.md          # 包含 Props、Events、Methods（重叠）
├── Events事件.md       # 与上面重复
```

### 3.2 就近原则

- 逻辑相近的资源应该放在一起
- 同一个修改原因影响的文件应该放在相近位置

**示例**：
```
✅ 正确：
组件文档/
├── Button.md
├── Button.types.md    # 与 Button 相关的类型文档
└── Button.styles.md   # 与 Button 相关的样式文档

❌ 错误：
组件文档/
├── Button.md
类型文档/
├── Button.types.md    # 与 Button 分离，不便查找
```

### 3.3 一致原则

- 目录/文件命名保持一致的规范
- 目录内容要和目录名称相符
- 文档结构保持一致

**命名规范**：
```
✅ 正确：
├── 如何自定义样式.md
├── 如何处理事件.md
├── 如何优化性能.md

❌ 错误：
├── 如何自定义样式.md
├── event-handling.md     # 命名风格不一致
├── 性能优化指南.md        # 命名风格不一致
```

## 四、内容组织模式

### 4.1 问题-解决方案结构

适用于 How-to Guides：

```markdown
## 问题：如何实现用户认证？

**解决方案**：使用认证库按以下步骤操作...

### 步骤 1：安装
...

### 步骤 2：配置
...
```

### 4.2 任务导向组织

适用于 Tutorials：

```markdown
## 任务：构建用户管理系统

1. 设计数据模型
2. 实现用户注册
3. 实现用户登录
4. 添加权限控制
```

### 4.3 功能导向组织

适用于 Reference：

```
## 认证功能

### 基础认证
### 多租户支持
### SSO 集成
```

## 五、写作风格指南

### 5.1 语言规范

| 规范 | ✅ 正确 | ❌ 错误 |
|------|--------|--------|
| 使用主动语态 | "创建配置文件" | "配置文件应该被创建" |
| 简洁完整 | "初始化：`npm init`" | "为了初始化，你需要运行 npm init 命令" |
| 统一术语 | 始终使用"用户认证" | 混用"auth"、"认证"、"登录系统" |
| 解释术语 | "使用 JWT（JSON Web Token）" | 直接使用 "JWT" |

### 5.2 代码示例规范

```markdown
✅ 正确：
\`\`\`bash
# 初始化项目
npm init

# 预期输出：
# ✅ 项目初始化成功
\`\`\`

❌ 错误：
\`\`\`bash
npm init
\`\`\`
（没有注释和预期输出）
```

### 5.3 格式规范

| 元素 | 规范 |
|------|------|
| 标题 | 使用 `#` `##` `###` 层级，不跳级 |
| 列表 | 使用 `-` 或 `1.`，保持一致 |
| 代码 | 使用 \`\`\` 包裹，指定语言 |
| 链接 | 使用 `[文本](URL)` 格式 |
| 强调 | 使用 `**粗体**` 或 `*斜体*` |
| 表格 | 使用标准 Markdown 表格格式 |

## 六、文档质量保证

### 6.1 自检清单

**准确性**：
- [ ] 内容是否正确？
- [ ] 是否与当前版本匹配？
- [ ] 链接是否有效？
- [ ] 代码示例是否可运行？

**可读性**：
- [ ] 语言是否清晰？
- [ ] 结构是否支持扫描？
- [ ] 标题是否描述性强？
- [ ] 是否有足够的代码示例？

**用户价值**：
- [ ] 是否解决真实问题？
- [ ] 是否易于找到？
- [ ] 是否有清晰的下一步？

**时效性**：
- [ ] 是否有版本信息？
- [ ] 是否有更新日期？
- [ ] 是否有变更记录？

### 6.2 文档审查模板

```markdown
## 文档审查：[文档标题]

**审查人**：[姓名]
**日期**：[日期]

### 整体评估
- [ ] 优秀 - 可以发布
- [ ] 良好 - 需要小修改
- [ ] 需改进 - 需要大修改

### 内容准确性
- [ ] 技术信息正确
- [ ] 示例可运行
- [ ] 链接有效

### 可读性
- [ ] 语言清晰易懂
- [ ] 结构支持用户目标
- [ ] 格式一致

### 改进建议
1. ...
2. ...
```

## 七、文档维护

### 7.1 版本管理

- 文档与代码同步更新
- 使用 Git 管理文档版本
- 每次修改添加 commit message

### 7.2 更新流程

1. **代码变更时**：同步更新相关文档
2. **定期审查**：每季度审查一次文档
3. **用户反馈**：根据用户反馈改进文档

### 7.3 文档元信息

每个文档应包含：

```markdown
---
title: 文档标题
description: 文档描述
lastUpdated: 2026-04-10
version: 1.0.0
---
```
